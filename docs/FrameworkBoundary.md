# iiGUI 그래픽 인터페이스 프레임워크 경계

iiGUI는 네이티브 그래픽 인터페이스의 컴포넌트, 배치, 입력, 장면, 접근성과
렌더링을 제공하는 C++ 프레임워크이다. QtQuick에 대응하는 것은 이 책임 범위이며
Qt API·QML 호환성이나 Qt 구현의 복제는 목표가 아니다. iiGUI는 LVUI 없이도
C++ 애플리케이션에서 사용할 수 있고 LVUI 타입·컴파일러에 의존하지 않는다.

LVUI는 선언형 UI 언어이다. 뷰 구조·스타일 입력·바인딩을 확인하고 C++ 코드로
생성하여 앱이 선택한 iiGUI 인터페이스에 연결한다. 앱 데이터와 작업은 가져온
C++ 객체가 소유하고 iiSDKCore의 쿼리 계약으로 연결한다. 일시적인 뷰 상태는
활성화에 속한다. 자세한 언어 경계는 [LVUI 책임 경계](../../LVUI/docs/GraphicsBoundary.md)를 따른다.

iiGUI는 OS 창·입력·글꼴·접근성 서비스 위에서 자체 컴포넌트를 GPU 장면으로
표시한다. 데스크톱 앱에 웹 브라우저를 내장하거나 컴포넌트를 OS 컨트롤로
구현하지 않는다. 디자인 시스템의 토큰·스타일은 값이나 교체 가능한 입력으로
받으며 특정 앱이나 LVUI 저장소를 참조하지 않는다. 실제 GPU·CPU 처리 경계와
기존 시스템 메뉴 등은 [GPU 장면 합성](GpuSceneComposition.md)에 기록한다.

## 앱 프로세스가 소유하는 표시 경로

네이티브 앱의 뷰는 앱 프로세스에 있는 iiGUI가 위젯 상태와 기하, 입력, 장면,
그리기 명령을 소유하고 직접 렌더링한다. LVUI는 뷰의 선언과 바인딩을 앱의 C++
위젯 트리에 연결한다. UI를 별도의 브라우저·웹 엔진·외부 렌더링 프로세스 또는
OS 기본 위젯에 맡겨 대신 구성하지 않는다. 앱은 변경된 상태에 대응해 필요한
장면을 제출하며, 변하지 않은 장면과 GPU 자원은 재사용한다.

픽셀 수준의 출력은 iiGUI가 준비한 기하·텍스처·셰이더와 GPU 명령으로 생성한다.
CPU에서 앱 내부의 글꼴 래스터화나 이미지 처리를 수행해 GPU로 합성하는 것도
이 소유권 안에 속한다. 모든 계산을 GPU에서 해야 한다거나 모든 글리프가 현재
GPU에서 래스터화된다는 의미는 아니다. 운영체제 창·표면, 입력기·글꼴·접근성,
GPU 드라이버와 데스크톱 컴포지터는 플랫폼 서비스다. 일반적인 창 시스템에서는
앱이 물리 디스플레이의 스캔아웃을 독점하거나 다른 창의 합성을 우회하지 않는다.
Web 타깃은 네이티브 데스크톱 앱에 브라우저를 내장하는 경로와 구분한다.

이것은 목표 계약이며 기존 모든 경로가 이미 충족되었다는 뜻은 아니다. 시스템 메뉴 등 알려진 예외와 하드웨어
선택·글꼴 처리의 현재 범위는 [GPU 장면 합성](GpuSceneComposition.md)을 따른다.
플랫폼별 실제 실행이나 물리 GPU 사용 여부는 별도로 검증해야 한다.

## 상태와 리소스 사용 원칙

앱은 iiSDKCore의 런타임·관측 및 쿼리 계약으로 도메인 상태와 변경을 제공하고,
iiGUI는 위젯의 일시적 입력·포커스·배치와 시각 상태를 소유한다. LVUI 바인딩은
양쪽을 연결하며 별도의 UI 엔진이 상태를 소유하지 않는다. 뷰는 이벤트와 구독한
쿼리의 변경에 반응한다. 값이 바뀌지 않으면 불필요한 통지·레이아웃·그리기를
피하고, 명시적으로 요청하지 않은 상태 폴링을 추가하지 않는다. 애니메이션과
게임처럼 프레임이 필요한 작업은 활성 기간에만 프레임을 요청한다.

네이티브 렌더러는 Metal·Direct3D·Vulkan 등 플랫폼 그래픽 API에 직접 자원과
명령을 제출한다. 변경되지 않은 기하·텍스처·장면은 재사용하고, 표시 순서와
클립을 보존하는 호환 작업을 묶는다. 가시 영역과 자원 수명은 실제 수요에 맞춰
관리하고 위젯 퇴역 시 구독과 보유 자원을 해제한다. 이는 자원의 사용을 줄이기
위한 설계 기준이지 모든 경로에서 최솟값이 측정되었거나 부분 손상 렌더링이
완성되었다는 보증은 아니다. 현재 경로별 제한은 [그래픽](Graphics.md)과
[GPU 장면 합성](GpuSceneComposition.md)에 기록한다.

## 현재 구현과 이전 경계

현재 iiGUI의 `WidgetState`는 자체 위젯 트리, 입력, 레이아웃, 접근성 및 GPU
장면을 제공한다. 그러나 LVUI의 컴파일러와 `src/Controls`, `src/Editing`,
`src/Collections` 등에는 위젯 상태·모션·그리기와 편집 동작이 남아 있다.
이 사실은 목표 경계가 이미 완성되었다는 뜻이 아니다.

진행 표시기는 `iiGUI/ProgressIndicator.h`의 `ProgressIndicator`가 상태·기하·
접근성·그리기와 모션을 소유한다. LVUI는 디자인 토큰과 관측된 값을 전달한다.
`iiGUI/Divider.h`와 `iiGUI/NativeDivider.h`는 구분선의 상태, 배치, 그리기와
메뉴 통합용 약한 연결을 소유한다. `ImageModel`, `NativeImageView`, `AvatarModel`,
`NativeAvatarView`는 이미지와 아바타의 상태·기하·접근성·그리기를 소유하며
아바타 심벌과 색상은 앱이 주입한다. `SheetModel`과 `NativeSheetView`는 시트의
상태·배치·입력·모션·수명을 소유하며 닫기 컨트롤은 앱이 공급할 수 있다.
이 컴포넌트들은 LVUI와 다른 SDK에 의존하지
않고 iiSDKCore 런타임 및 플랫폼 서비스로 실행된다. 정적인 진행 표시기는 프레임
핸들러를 만들지 않고, 반응형 표시기도 실제 보간 중에만 프레임을 요청한다.
나머지 컴포넌트 구현은 아직 이전 대상이다.

`iiGUI/ButtonModel.h`는 앱이 전달한 색상 값으로 버튼의 활성·포커스·선택·
호버·누름 상태를 판정하고 아이콘과 텍스트의 기하를 계산한다. 앱은 명시적
선택 색상과 기준 액센트·표면 색상을 제공할 수 있으며, 잘못된 입력은 마지막
유효 설정을 유지한다. `ButtonModel`은 독립 C++ API이고 `BasicButton`은 같은
계산을 다른 값 계약으로 사용할 수 있는 정책 기반 API다. 두 타입은 특정
디자인 토큰이나 LVUI에 의존하지 않는다.

`iiGUI/NativeButtonView.h`의 `NativeButton`은 이 모델과 입력·접근성·기하·
모션·그리기 및 위젯 수명을 연결한다. `BasicNativeButton<Policy>`는 앱이 소유한
값과 콜백 계약을 받아 같은 호스트 구현을 사용한다. LVUI의 네이티브 버튼은
이 정책을 통해 디자인 토큰·아이콘 공급자·메서드를 주입한다. iiGUI는 LVUI를
찾거나 링크하지 않는다. `ButtonTiming`의 기본 시간은 0이며 앱이 각 상태의
모션 시간을 제공한다. 실제 보간이 진행될 때만 프레임을 요청한다.

`ButtonIconSource`는 이름·크기와 공급자의 리비전으로 불변 이미지를 제공한다.
동일한 요청은 보유한 이미지를 재사용하고, 실패한 갱신은 기존 버튼 상태를
유지한다. 공급자가 내용을 변경하면 리비전을 바꾸고 앱이 변경을 통지해야 한다.
기존 `LVUI/Button.h`에는 다른 컴포넌트에서 사용하는 구형 값 모델이 아직 남아
있으며, LVUI의 어댑터와 다른 컴포넌트의 iiGUI 직접 참조도 계속 이전해야 한다.

`iiGUI/AlertButtonModel.h`와 `iiGUI/NativeAlertButtonView.h`는 경고 버튼의
상태·스타일 계산과 입력·접근성·그리기·수명을 소유한다. 독립 C++ 소비자는
`AlertButtonModel`과 `AlertButtonView`를 사용하며, 정책 기반 API로 앱의 색상·치수와
콜백을 제공할 수 있다. 동일 설정은 다시 적용하지 않고, 유효하지 않은 설정은
기존 상태를 보존한다. LVUI 토큰과 기존 이벤트 계약은 현재 LVUI 정책 어댑터가
연결한다. 구형 LVUI 경고 버튼 모델은 제거했으며 경고창과 모달도 같은 iiGUI
모델을 사용한다. LVUI 정책 어댑터의 iiGUI 직접 참조는 아직 남아 있다. macOS arm64에서 iiGUI 모델·호스트·독립 설치 소비자와 LVUI 생성·
경고창·모달 조합을 헤드리스 검사했다. 실제 창과 다른 운영체제는 검사하지 않았다.

`iiGUI/ToolbarButtonModel.h`와 `iiGUI/NativeToolbarButtonView.h`는 도구 버튼의
상태·크기·아이콘과 텍스트 기하, 입력·접근성·그리기와 위젯 수명을 소유한다.
독립 소비자는 `ToolbarButtonModel`과 `ToolbarButtonView`를 사용하고 색상과
래스터 아이콘 또는 리비전을 가진 아이콘 공급자를 지정한다. 같은 입력은 다시
적용하지 않으며, 실패한 아이콘이나 유효하지 않은 설정은 현재 버튼을 유지한다.
클릭 도중 설정을 변경하거나 위젯을 폐기하면 이전 ID의 후속 콜백은 전달하지
않는다. LVUI는 현재 토큰과 기존 값·아이콘 공급자를 정책 어댑터로 전달한다.
구형 LVUI 도구 버튼 계산 모델은 제거되었다. `HierarchyToolbarLayout.h`는
계층 도구 모음의 가변 슬롯 배치와 입력 검증을 제공하며 슬롯 여백과 간격은 앱이
공급한다. LVUI 호스트 어댑터의 iiGUI 직접 참조는 아직 남아 있다. macOS arm64에서 독립 모델·호스트·설치 소비자와 LVUI 목록·
계층 도구 모음 조합의 헤드리스 검사가 통과했다.

`iiGUI/ListFooterModel.h`와 `iiGUI/NativeListFooterView.h`는 목록 하단의 세 슬롯,
가변 폭 배치, 명령·입력·아이콘·위젯 수명을 소유하고 도구 버튼을 조합한다.
독립 소비자는 `ListFooterModel`, `ListFooterView`, `FooterInput`과 `FooterSlot`을
사용한다. 슬롯 자산과 메뉴 표시자·여백은 호출자가 제공할 수 있다. 입력이 같으면
아이콘을 다시 해석하지 않으며, 공급자 변경은 앱이 리비전 입력으로 게시한다.
명령이 설정을 바꾸거나 화면을 폐기하면 이전 슬롯의 후속 콜백을 전달하지 않는다.
LVUI 정책은 기존 토큰·명령·자산을 연결한다. 구형 LVUI 푸터 배치 모델은
제거했고 목록과 계층 패널도 같은 iiGUI 모델로 검증한다. 정책 어댑터의 iiGUI
직접 참조는 아직 남아 있다. macOS arm64에서 독립 모델·호스트·설치 소비자와
LVUI 목록·계층 패널 및 복합 행의 헤드리스 검사가 통과했다.

`iiGUI/ListToolbarModel.h`와 `iiGUI/NativeListToolbarView.h`는 목록 상단의 세
아이콘 슬롯에 대한 기하·입력·접근성·그리기와 위젯 수명을 소유한다. 독립 앱은
`ListToolbarModel`, `ListToolbarView`, `ListBarInput`을 사용하고 색상과 아이콘
공급자를 지정한다. 같은 입력은 다시 적용하지 않으며 변경된 공급자 내용은 앱이
리비전 입력으로 게시한다. 공급자 조회 중 기존 입력을 다시 요청해도 진행 중인
오래된 후보가 이를 덮지 않는다. 화면이 퇴역하면 나머지 아이콘 조회를 중단하고
외부 핸들이 남아 있어도 캐시·공급자·콜백을 해제한다. 슬롯을 배치하는 동안 새
설정이 재진입하면 이전 배치의 나머지 슬롯을 적용하지 않는다. 단독 LVUI 선언은 생성된 앱이 iiGUI를 직접
조합하며 토큰과 자산을 전달한다. 구형 LVUI 기하 모델은 제거했고 목록 패널도
같은 iiGUI 모델로 검증한다. 목록 패널용 정책 어댑터의 iiGUI 직접 참조는 아직 남아 있다. macOS arm64에서
독립 모델·호스트·설치 소비자와 LVUI 목록 패널 조합을 헤드리스 검사했다.

`iiGUI/NativeIconView.h`의 `IconView`는 아이콘의 크기·접근성·이미지 위젯과
수명을 소유한다. 앱은 `IconViewInput`에 이름과 교체 가능한 래스터 공급자를
전달하고 공급자 변경을 리비전 입력으로 게시한다. 같은 입력은 공급자를 다시
호출하지 않지만, 해석 중 기존 값을 다시 요청해도 그 최신 요청이 우선한다.
위젯 퇴역 시 공급자와 캐시를 해제하며, 공급자 조회 중 화면과 공개 핸들이
함께 폐기되어도 진행 중인 작업이 캐시를 다시 채우지 않는다. 유효하지 않은
후보는 현재 이미지를 보존한다. LVUI의 기존 아이콘 위젯 헤더는 제거했고 생성된 앱이 디자인 자산을
iiGUI와 연결한다. `SvgImageCache`가 디코딩 결과의 제한된 공유 캐시를 소유하며
LVUI 자산 계약은 앱이 공급하는 디코더에 의존한다. macOS arm64에서 iiGUI 독립 호스트·설치 소비자와 LVUI 생성·
자산 캐시·패키지 경계 검사를 통과했다. 실제 운영체제 표시는 검사하지 않았다.

`iiGUI/ModalModel.h`는 모달의 액션 선택과 크기·위치·모서리 계산을 제공한다.
`iiGUI/NativeModalView.h`는 팝업 위젯 트리, 액션 입력, 열림·닫힘 모션과 본문
활성화 수명을 소유한다. `BasicNativeModal<Policy>`를 사용하는 조합은 표시 값,
색상, 버튼 스타일, 아이콘 공급자와 콜백을 외부에서 제공할 수 있다. 본문은 열기
