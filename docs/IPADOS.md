# iPadOS 네이티브 호스트

`CMAKE_SYSTEM_NAME=iOS`는 AppKit 대신 UIKit 창·장면 수명과 자체 C++ 위젯 표면을 선택한다. 최종 진입점과 작업·프레임 루프는 iiSDKCore가 소유하며, 주 창의 드라이버가 `UIApplicationMain`에 진입한다. Qt, QML, WebKit은 사용하지 않는다.

설치된 iiGUI의 CMake 패키지는 같은 설치 접두어에 있는 LunaSVG와 PlutoVG를
iOS 교차 컴파일의 검색 루트 설정과 관계없이 찾는다. 소비자가 별도 패키지 경로를
명시한 경우에는 그 경로를 우선한다. Core와 Vulkan은 대상 플랫폼에 맞는 설치본을
소비자가 지정해야 하며, macOS 라이브러리를 iPhoneOS 링크에 대용하지 않는다.
UIKit 구현과 정적 MoltenVK가 사용하는 Foundation·CoreGraphics 프레임워크는
iiGUI의 링크 계약에 포함되므로 앱이 별도로 추가할 필요가 없다.

## 플랫폼 경계

- `HostIOS.mm`: 독립 `UIWindowScene`과 같은 장면의 비모달 보조 `UIWindow`, 안전 영역·회전, CADisplayLink, Core 작업 깨우기, 문서 선택기와 보안 범위 URL을 연결한다. 배경 전환 시 표시 링크와 GPU 제출을 중단하고 복귀 시 프레임 시계를 초기화한다.
- `NativeWidgetsIOS.mm`, `UIKitTextInputIOS.mm`: 하나의 UIView 위에 iiGUI 위젯의 그리기 목록을 표시하고 UIKit 텍스트 서비스, 하드웨어 키보드, 접근성 요소, 손가락·Pencil 샘플, 터치 누름의 `UITouch.tapCount`, 한 손가락·Pencil 뷰포트 스크롤, 두 손가락 이동과 핀치를 C++ 입력으로 전달한다. 단일 포인터의 세로 스크롤은 스크롤 가능한 뷰포트에서만 시작하며 가로 슬라이더와 캔버스 입력을 구분한다.
- `CanvasMetal.mm`, `TextMac.mm`, `TextLineMac.mm`: Apple 공통 GPU·CoreText 구현을 UIKit/AppKit 경계에서 나눈다. iPadOS는 좌상단 좌표와 UIFont를 사용한다.
- `VulkanWindowIOS.mm`: Vulkan Metal surface를 UIView의 CAMetalLayer에 연결한다. `Renderer::automatic`은 Metal을 우선하고, `Renderer::vulkan`은 별도 Vulkan 경로를 선택한다. iPadOS에서 Vulkan은 MoltenVK를 통해 Metal 장치를 사용한다.
- `DesktopIOS.mm`: UIKit 클립보드와 외부 URL을 제공한다.

## 창의 콘텐츠 영역

iPadOS 창의 앱 콘텐츠는 기본적으로 컨트롤러의 전체 뷰 경계를 사용한다. 상단
상태 표시줄과 하단 홈 표시기 때문에 전달되는 안전 영역을 콘텐츠 크기에서 빼지
않으므로 그 아래에도 앱 화면을 그린다. 상태 표시줄과 홈 표시기의 가시성·시스템
제스처는 별도의 운영체제 정책이며, 콘텐츠 확장 자체가 이를 숨기거나 변경하지는
않는다. 분할 화면과 크기 조절에서는 물리 디스플레이 전체가 아니라 현재 장면의
창 경계를 따르고, 회전이나 창 크기 변경 뒤에도 위젯 표면과 호스트 크기를 함께
갱신한다. `iiGUI.uikit_fullscreen_layout`은 장면·컨트롤러·위젯 표면의 소스 연결을
검사하며, 실제 기기의 시스템 막대와 터치가 검증되었다는 뜻은 아니다.

## UIKit 텍스트 입력 계약

UIKit 텍스트 서비스는 포커스된 iiGUI 텍스트 제공자의 UTF-16 문서·선택·조합을
읽고, 후보 교체·확정과 선택을 해당 제공자에 전달한다. 조합 선택은 후보 시작을
기준으로 하며 서로게이트를 나누는 편집과 범위 밖 요청은 원자적으로 거절한다.
조회는 제한된 범위만 읽고 문서 버전과 포커스 세대를 재검사한다. UIKit이 조회한
문자열은 서로게이트 일부를 포함할 수 있지만 잘못된 경계의 수정은 허용하지 않는다.
빈 후보는 조합 취소가 아니라 빈 조합으로 표현한다.

텍스트 위치와 범위는 해당 입력 위젯과 포커스 세대에 속하며 위젯 교체나 포커스
이탈 후에는 재사용하지 않는다. 입력기 요청의 실제 전달에는 iiGUI 텍스트 상태
버전을 사용하며, 버전 없는 사용자 제공자는 조합 편집을 안전하게 사용할 수 없다.
커서와 보이는 선택 사각형은 제공자의 텍스트 기하와 표면 좌표를 사용한다.
기본 입력 필드의 네이티브 입력과 외부 텍스트 설정, LVUI 입력 필드와 코드
편집기의 지정된 변경은 UIKit 입력 델리게이트에 변경 전후로 알린다. 사용자 정의
제공자는 같은 알림이 필요한 외부 편집을 `begin_text_input_change` 범위로 감싼다.
UIKit 자체 요청에는 중복 알림을 보내지 않으며 그 안에서 재진입한 앱 편집은 별도로
알린다. 텍스트 조회는 한 번에 최대 65,536 UTF-16 단위이다.

현재 조합 범위 밖으로 선택을 옮기는 요청은 후보의 확정과 새 선택을 하나의
버전 검사 편집으로 처리한다. 요청 범위가 잘못되거나 길이 제한을 적용한 결과에서
그 범위가 유효하지 않으면 후보와 문서를 그대로 유지한다. 범위가 유효하면 길이
제한을 적용한 텍스트에 동일한 위치의 선택을 설정한다. 확정 문자열로 표시
문서의 범위를 교체하는 요청은 조합 안팎과 걸치는 범위를 하나의 편집으로 처리한다.
사용자 정의 제공자가 이 계약을 지원하지 않으면 요청을 거절할 수 있다. 포커스를 유지한 외부 편집 뒤 기존 위치 객체를 새 텍스트에
맞춰 재배치하지 않는다. 가로 이동은 논리적 자소 순서이며 완전한 양방향 시각 순서
이동은 아직 제공하지 않는다. 세로 이동은 보이는 줄의 기하에 한정된다. 시스템이
제공하는 조합 스타일은 저장하지만 그리기에 적용하지 않는다. 이 계약과 실제 기기의
시스템 키보드·손글씨·보조 기술 검증은 별개이다.

## 지원과 검증의 구분

iPadOS 장면의 주 창 크기는 운영체제가 관리하므로 `set_content_size`와 데스크톱 최소화·최대화 요청은 `unsupported`이다. 보조 창은 요청한 크기를 사용 가능한 장면에 맞춰 제한한다. 저장 위치 선택은 문서 선택기로 폴더를 고른 후 요청 파일명을 붙이는 방식이다. 보안 범위 접근은 호스트가 닫힐 때 해제한다.

운영체제가 크기를 관리하는 장면에서 LVUI 창 선언의 최초 게시에는 크기와 최소
크기가 함께 전달될 수 있다. 이 최초 값은 힌트로 취급하여 네이티브 크기 변경을
요청하지 않으며, 동시에 전달된 제목은 적용한다. 최초 게시 이후의 명시적인 크기
변경은 기존과 같이 `unsupported`이다. 최초 게시에 속성이 없었더라도 후속 변경을
초기 힌트로 혼동하지 않는다. 같은 장면에 겹쳐 표시하는 기존 보조 창은 원래의
크기 변경 동작을 유지한다.

UIKit의 파일 URL 열기 요청은 주 호스트의 소유 스레드에서 제한된 공통 파일
대기열에 접수하고 창이 준비된 뒤 `HostCallbacks::files_opened`에 전달한다.
대기 경로의 UTF-8 검증과 최대 개수·바이트 수는 [Cocoa 파일 요청 접수](HostPlatforms.md#cocoa-파일-열기-요청-접수)와
같다. 유효하지 않은 요청이나 용량 부족은 조용히 버리지 않고 호스트 오류로
기록한다. 보안 범위 접근이 승인된 URL은 호스트 정리 때 해제한다. 이 계약은
기기에서 문서 권한이나 실제 앱 실행이 검증되었다는 뜻이 아니다.

앱 전경·백그라운드 전환은 개별 장면의 포커스와 분리해 `UIApplication`의
프로세스 전체 알림으로 전달한다. 열린 앱이 백그라운드로 바뀌면 운영체제가
앱을 중단하기 전에 콜백 전달을 시도하지만, 강제 종료나 즉각적인 중단에서
콜백 실행 또는 백그라운드 실행 시간이 보장되지는 않는다.

### UIKit 장면 연결과 재연결 계약

단일 창 호스트는 처음 연결된 `UISceneSession`의 식별자와 현재 `UIWindowScene`
인스턴스를 구별한다. 다른 세션의 연결과 이전 인스턴스의 지연된 활성·비활성·연결
해제 이벤트는 기존 창과 앱 상태를 변경하지 않는다. 같은 인스턴스의 중복 연결도
창을 다시 게시하지 않는다.

현재 장면이 연결 해제되면 창과 같은 장면의 보조 창을 숨기고 장면에서 분리하며
프레임 전달을 중지한다. 세션이 보존된 동안에는 앱과 뷰의 수명을 유지한다. 같은
세션이 새로운 장면 인스턴스로 재연결되면 기존 창들을 다시 부착하고 현재 UIKit
활성 상태를 적용한다. 보조 창의 마지막 크기는 새 장면의 사용 가능 영역에 맞춰
유지한다. 세션이 영구 폐기된 경우 연결을 해제하고 식별자를 비워,
이후 새 세션에 기존 단일 창 호스트를 다시 부착할 수 있다. 재연결만으로 `opened`
콜백을 반복하지 않는다. 독립 장면을 소유하는 앱 드라이버는 아래의 별도
라우팅 계약을 사용한다. 파일 열기는 기존처럼 앱 전체 요청으로 접수한다.

현재 재연결은 같은 프로세스의 창·위젯 상태와 표시 표면을 유지한다. 따라서 장면
연결 해제 시 표시 관련 메모리가 모두 회수되는 것은 아니며, 프로세스 종료 후의
상태 복원을 제공하지 않는다. 연결 해제 정리 도중 새로운 연결이 재진입하면 이전
세대의 나머지 정리는 새 연결을 변경하지 않는다.

### 독립 장면 요청의 라우팅 계약

독립 창의 장면 활성화 요청은 운영체제가 비동기로 완료하므로 각
요청에 고유 토큰을 부여한다. 소유 스레드의 라우터는 토큰과 세션 식별자 및 현재
장면 인스턴스를 구별하여 연결한다. 연결 순서가 요청 순서와 달라도 해당 창에만
전달하며, 이미 연결된 세션을 다른 토큰이나 장면이 가로챌 수 없다. 장면 연결
해제는 세션과 창의 소유권을 유지하고 같은 세션의 재연결을 허용한다. 세션의
영구 폐기는 그 창만 퇴역시킨다.

창이 연결되기 전에 요청이 취소되면 토큰의 취소 기록을 보존한다. 이후 도착한
장면은 기존 창이나 재사용된 창 세대에 연결하지 않고 운영체제에 폐기를 요청할
수 있어야 한다. 활성화 실패는 아직 연결되지 않은 요청만 퇴역시키며, 중복·지연
오류는 이미 연결된 창을 제거하지 않는다. 라우팅은 소유 스레드에서 수행하며,
요청 수에는 상한을 두고 빈 식별자와 충돌을 거부한다. 앱 드라이버는 첫 장면을
첫 선언 창에 할당하고 자체 이벤트 펌프를 창과 독립적으로 유지한다. 다른 창은
각각 새 세션을 요청한다. 개별 장면의 활성 상태를 모아 앱 활성 상태를 전달하며,
창을 닫을 때는 UIKit에 세션 폐기를 요청한다. 장면 설정이나 기기가 다중 장면을
허용하지 않으면 창 생성은 `unsupported`이다.
자식 창의 닫힘 통지를 앱 큐에 넣지 못하면 오류를 기록하고 앱 이벤트 루프를
중단한다. 앱 전체 종료가 이미 큐의 접수를 중단한 경우에는 남은 창을 Core 정리
순서에서 분리한다.

요청과 연결되지 않은 운영체제 장면은 기존 창 세대에 임의로 할당하지 않는다.
프로세스 재시작 후 장면을 선언에 복원하는 기능은 제공하지 않는다. 이 구현은
헤드리스 라우팅 검사와 iPhoneOS 교차 컴파일 대상으로, 실제 UIKit 장면의 생성·
복원·폐기 및 실기기 동작은 별도 검증이 필요하다.

2026-11-04에 변경된 `HostIOS.mm`을 iPhoneOS 18 이상 arm64 대상으로 객체까지
컴파일했다. 공통 파일 대기열을 포함한 호스트 헤드리스 검사 8건이 macOS에서
통과했다. iPadOS 라이브러리 전체 링크, 보안 범위 권한 및 실기기 파일 열기는
검증하지 않았다.

같은 날 앱 전경 전환을 추가한 호스트와 LVUI 생성 앱은 iPhoneOS 18 이상
arm64 객체로 각각 컴파일했다. 이 확인에는 iPadOS 앱 전체 링크와 실기기
전경·백그라운드 전환이 포함되지 않는다.

2026-11-05 UIKit 세션 식별과 재연결을 추가한 후 macOS에서 관련 헤드리스
호스트 검사 9건이 통과했고, 세션 상태 검사는 ASan·UBSan도 통과했다. 변경된
UIKit 호스트와 상태 검사 소스는 경고를 오류로 처리하여 iPhoneOS 18 arm64
객체로 컴파일했다. LVUI 생성 앱 진입점도 같은 대상으로 객체 컴파일했으며,
첫 시도는 iiColorManager 헤더 경로 누락으로 실패한 뒤 해당 SDK 경로를 명시해
통과했다. Qt·LVRS SDK 경로를 차단한 검사에서 세 번역 단위의 의존성 목록에도
해당 헤더는 없었다. 이 결과는 iPadOS 라이브러리 전체 링크, 실제 장면 연결·메모리
회수·입력 또는 기기 실행을 검증한 결과가 아니다.

기존 UIKeyInput 경로는 버전 없는 제공자의 확정 문자열 입력과 삭제에 대한 호환
경로로 남는다. 외부 드래그 앤드 드롭은 이 구현의 검증 범위에 포함하지 않는다.
Pencil 압력·기울기 변환의 자동 테스트 통과와 실제 Pencil 하드웨어 필기 검증을
구분해야 한다.

UIKit은 앱 종료 대신 장면 수명을 관리한다. Core 종료 요청은 창과 작업을 정리하며, 진단 실행의 결과는 파일·콘솔에서 확인한다. 기기 진단 후 일반 실행으로 돌아갈 때는 개발 도구가 해당 앱 프로세스를 종료하고 다시 실행한다.

주 호스트의 닫힘 알림은 진행 중인 iiGUI 네이티브 콜백이 모두 반환된 뒤 전달한다.
iiGUI의 Core 연결은 이 알림을 메인 큐에 한 번 더 이연한 후
`Application::driver_stopped()`를 호출해 UIKit 이벤트 루프가 계속 살아 있어도 앱
스코프와 소유 작업을 정리한다. 사용자 닫힘 콜백이 중첩 이벤트 루프를 실행하더라도
그 콜백이 반환하거나 예외를 발생시킨 뒤에 정리 작업을 예약한다. 메인 큐가 실행되기 전에 드라이버가 반환하면 대기한
완료 알림은 무효화한다. 운영체제의 강제 종료나 즉시 중단 시 메인 큐가 실행된다는
보장은 없다. 완료된 Core 앱을 같은 프로세스에서 다시 시작하는 기능은 별도이다.
중첩 콜백과 취소된 지연 완료, 중복 전달은 헤드리스 검사로 확인했다. UIKit 호스트와
Core 연결 소스는 iPhoneOS 18 arm64로 교차 컴파일했고, 이전 Core 헤더를 명시적으로
거부하는 컴파일 검사도 통과했다. 실제 장면 종료와 기기 실행의 검증은 아니다.

일반 창의 `opened` 알림은 해당 UIKit 컨트롤러의 `viewDidAppear`가 끝난 뒤 전달한다.
독립 앱 드라이버는 초기 장면 연결 뒤 창 없는 이벤트 펌프를 먼저 시작하고, 각
독립 창의 `opened`는 그 창의 appearance 완료를 기다린다. 기기 검사에서는 생성·
취소·재생성·종료를 실제로 반복하고 appearance 불균형 경고의 유무를 함께 확인한다.

## 빌드와 검사

arm64, iPhoneOS SDK, iOS 18.0 이상과 동일한 대상의 iiSDKCore·LVUI·Vulkan 패키지를 사용한다. macOS 라이브러리를 iOS 링크에 섞지 않는다. 교차 빌드에서 LVUI AOT 생성기를 실행할 때는 macOS용 `LVUI_HOST_COMPILER`를 명시한다. `tests/mobile_input.cpp`는 좌표·접촉 식별자, 압력 정규화, 기울기, 해제와 비유한 값 처리를 검사한다. CMake의 `iiGUI.mobile_input`으로 등록되며, 실제 창·GPU·문서 실행은 소비 앱의 연결 기기 검사로 별도 검증한다.

2026-11-05에 Core·iiGUI·LVUI를 iPhoneOS arm64 정적 런타임으로 빌드하고,
생성된 LVUI 다중 창 앱을 각각의 임시 설치본에 연결했다. Vulkan은 공식 MoltenVK
1.4.2 iOS 배포본을 사용했으며 다운로드 SHA-256은
`b5d947b1660e6e9fed40b9cd2387e160aaab9e80b775c0cef7e14059405178c1`이다.
Qt·LVRS 경로를 차단한 링크와 번들 장면 설정, UIKit 델리게이트 클래스의 바이너리
포함을 확인했다. 장면 라우터의 헤드리스 검사는 ASan·UBSan에서도 통과했다.
이는 앱을 띄우거나 iPad에서 실제 장면 생성·전환·폐기를 검증한 결과가 아니다.

같은 날 UIKit 텍스트 연결 후 Core·iiGUI·LVUI를 다시 iPhoneOS arm64 대상으로
빌드하고, 다중 창과 `InputField`·`CodeEditor`를 각각 포함하는 LVUI 생성 앱을
임시 설치본에 링크했다. 텍스트 앱 바이너리에 조합·선택·커서·삭제를 위한 UIKit
메서드가 포함되고 두 바이너리의 직접 동적 의존성에 Qt·QML·LVRS가 없음을 확인했다.
macOS 헤드리스 iiGUI 입력·선택·기하·접근성 검사 6건과 LVUI 입력 필드·코드
편집기 검사 2건도 통과했다. 이 결과는 장치의 UIKit 입력기나 그래픽 실행 검증이 아니다.

이후 조합 범위 밖 선택과 조합 중 범위 교체를 추가한 뒤 iiSDKCore·iiGUI·LVUI를
iPhoneOS arm64로 다시 빌드하고 다중 창 및 텍스트 입력 생성 앱을 링크했다.
두 앱의 직접 동적 의존성과 텍스트 앱의 UIKit 메서드를 검사했으며, 실제 앱이나
시스템 키보드는 실행하지 않았다. macOS 헤드리스 검사는 빈 후보, 후보 안팎과
경계를 걸치는 교체, 잘못된 UTF-16 경계, 길이 제한 및 변경 중 리비전 충돌을
확인한다. [Apple의 markedTextRange 계약](https://developer.apple.com/documentation/uikit/uitextinput/markedtextrange?language=objc)은
조합 중 선택이 표시된 후보 안에 있어야 한다고 정의한다.
