# 웹 캔버스 크기와 반응형 배치

웹 호스트는 브라우저 창 크기 변경과 기기 배율 변경뿐 아니라 `ResizeObserver`로
`#canvas` 자체의 크기를 관찰한다. 페이지의 분할 영역이나 부모 레이아웃이 바뀌어
창의 크기는 그대로여도 기존 호스트 이벤트 경로를 깨워 논리 크기와 배율을 다시
측정한다. 크기나 배율이 바뀌면 iiGUI 위젯의 배치와 그리기를 무효화한다. 같은
값의 중복 알림은 배치 변경으로 전달하지 않는다. 관찰자는 호스트 종료 및 교체 시
연결을 해제하고, 늦게 도착한 이전 콜백은 무시한다.

CSS가 캔버스를 일시적으로 0×0 또는 한 축이 0인 크기로 만들면 마지막 유효
뷰포트를 보존하고 표시와 디스플레이 프레임을 중지한다. 유효한 크기로 돌아오면
시계를 재설정하고 크기가 이전과 같아도 그리기와 배치를 다시 요청한다. 문서의
포그라운드 상태는 브라우저 문서 가시성으로 따로 판단한다. 음수·비유한 값과 기존
크기·배율 한도를 벗어난 값은 오류로 처리한다. `ResizeObserver`가 없는 브라우저는
창 resize와 배율 변경만 관찰한다.

스레드가 활성화된 WebAssembly의 힙은 공유 메모리이다. 텍스트 측정·그리기와
클립보드의 UTF-8 디코딩은 공유 메모리의 뷰를 `TextDecoder`에 직접 넘기지 않고
일반 메모리에 복사한 입력을 전달한다. 브라우저가 공유 버퍼를 거절해 위젯
초기화나 클립보드 요청이 실패하지 않도록 하기 위한 경계이다.

웹의 편집용 `TextLine`은 아직 구현되지 않아 `unsupported`를 반환한다. 정적 텍스트
그리기와 텍스트 편집 지원은 별개이다. 텍스트 필드를 포함한 뷰의 초기화와 표 셀
편집은 현재 지원하지 않으며 IME도 제공하지 않는다. 표의 입력 이벤트로 시작한
편집이 미지원이면 오류를 표의 `failure()`에 보존하고 나머지 표 입력은 계속한다.
직접 편집 API는 `unsupported` 결과를 반환하고 다른 종류의 실패는 전달한다.

브라우저 이벤트 콜백은 브라우저 스레드에서 짧게 실행되고, 순서가 보존되는
제한된 큐를 통해 애플리케이션 스레드가 처리한다. 큐의 잠금을 보유한 상태에서는
위젯이나 브라우저 API를 호출하지 않는다. 포인터 이동과 연속된 크기 알림은
합칠 수 있지만 입력의 누름·놓음 순서는 유지한다. 큐가 가득 차면 조용히 입력을
버리지 않고 호스트 오류로 처리한다.

앱의 셸은 캔버스와 부모 요소의 CSS 크기를 지정해야 한다. C++에서 창 크기를
명시적으로 설정하면 호스트가 캔버스의 인라인 크기도 설정하므로, CSS가 크기를
소유해야 하는 셸은 해당 정책을 명시해야 한다. 스택의 정렬과 flex, 리스너의
크기 콜백과 뷰모델 바인딩은 플랫폼 공통 기능이다. 임의의 구성 요소가 모든 폭에
맞게 자동으로 재설계된다는 뜻은 아니다.

웹 셸의 캔버스에 `data-iigui-respect-minimum`을 지정하면 웹 호스트가 앱의 최소
창 크기를 CSS 최소 크기로 반영한다. 뷰포트보다 큰 고정 폭 콘텐츠는 브라우저
스크롤 영역에 남는다. 셸이나 부모 요소는 해당 축의 스크롤을 허용해야 한다.
기본값은 사용하지 않는 것이며, 임베딩 페이지가 캔버스
크기와 0 크기 숨김을 계속 직접 소유한다. 호스트는 시작 시 기존 인라인 최소
크기를 기억하고 종료할 때 복원한다. 페이지가 이후 인라인 값을 직접 바꾸면
그 변경을 덮어쓰지 않는다. `max()`로 결합할 수 없는 기존 CSS 최소 크기는
그대로 보존하며 해당 축에 이 정책을 적용하지 않는다. 앱의 최소 크기가 바뀌면
호스트가 소유한 CSS도 갱신한다.
이 정책은 뷰의 자동 재배치나 모바일 터치 스크롤 지원을 뜻하지 않는다.

캔버스에 `data-iigui-accessibility`를 지정하면 iiGUI 위젯 트리를 별도의 화면
표시 없이 브라우저 의미 트리로 투영한다. 텍스트, 버튼, 링크, 체크박스, 라디오
및 스위치의 이름·활성·선택 상태와 슬라이더·진행률의 범위를 전달한다. 피어의
포커스와 활성화, 라디오 방향키와 슬라이더 방향키·Home·End는 iiGUI로 전달한다. 피어는 화면 좌표 경계와 식별자를 제공하며 임베딩 호스트는 활성 피어에 포커스를 전달하거나 표면의 포커스를 해제할 수 있다.
피어는 위젯의 그림이나 상태를 소유하지 않는다. 현재 라디오 그룹 관계는 노출하지
않으며 편집 필드·표 등의 접근성은 이 경로에서 지원하지 않는다. 퇴역한 피어는 새 요청을 보내지 않고,
이전 표면에서 대기 중인 입력은 새 표면으로 전달하지 않는다.
캔버스가 숨겨지거나 그래픽 문맥을 잃으면 피어를 퇴역시키고, 표시나 문맥이
돌아오면 현재 위젯 상태에서 다시 만든다. 피어에 이름이 없는 컴포넌트는 셸이
임의의 이름을 만들지 않으므로 뷰에서 접근성 이름을 제공해야 한다.

2026-11-16 Emscripten으로 웹 호스트를 컴파일하고 LVUI 카운터 소비자에 링크했다.
캔버스 관찰자의 설치·교체·종료와 늦은 콜백은 Node 모의 객체로 검사했다. 0 크기
분류와 두 폭에서의 공통 위젯 배치·중복 크기 통지는 네이티브 헤드리스 테스트로
확인했다. 이 자동 테스트만으로 실제 브라우저와 모든 컴포넌트를 검증하지 않는다.
공유 메모리를 사용하는 Emscripten 테스트에서는 브라우저의 디코더 제약을 모의해
텍스트 측정·래스터화와 클립보드 쓰기를 확인하고, 별도 pthread 테스트에서 웹
이벤트 큐의 순서·포화·동시 접근을 확인했다.

같은 날 macOS arm64의 Chromium 157 기반 브라우저에서 LVUI 카운터를 실행했다.
1280×720과 390×844 뷰포트에서 버튼과 뷰모델 갱신을 확인했다. 별도의 임베디드
fixture에서는 창 크기를 유지한 채 캔버스의 CSS 크기를 720×480에서 320×480으로
바꾸고, 0×0으로 숨긴 후 720×480으로 복원해 배치와 기존 카운터 값, 복원 후
포인터·키보드 입력을 확인했다. 이 결과는 해당 예제와 브라우저의 검증이며 모든
위젯, 브라우저, GPU 또는 모바일 기기에서의 동작을 보증하지 않는다.

같은 브라우저에서 접근성 피어의 버튼·라디오·체크박스·스위치·슬라이더 상태와
키보드 조작을 확인했다. 0–10 슬라이더의 Home·End, 라디오 방향키와 체크박스의
Space가 iiGUI 값과 캔버스에 반영되었다. 캔버스를 숨기면 피어가 사라지고 복원하면
이전 카운터 값과 입력이 유지되었다. 실제 스크린리더, 다른 엔진과 모바일 입력은
검증하지 않았다.

단일 스레드 WebAssembly Core를 선택한 빌드에서는 iiGUI도 같은 단일 스레드
계약으로 빌드한다. 이 경로는 공유 메모리, 교차 출처 격리, OffscreenCanvas와
`Atomics.waitAsync`를 요구하지 않는다. 브라우저 메인 스레드에서 WebGL2로
그리며 실제 입력·마감·활성 프레임 이벤트가 있을 때만 비동기 대기를 깨운다.
텍스트 임시 캔버스는 OffscreenCanvas가 없으면 문서의 캔버스를 사용한다. 글자의 기준선은 글꼴의 상승·하강 지표와 줄 높이로 계산하며 지표가 없으면 줄 여백을 사용한다.
클립보드는 브라우저 권한과 보안 문맥을 따르며 완료 이벤트로 대기를 해제한다.
pthread Core를 선택한 빌드는 기존 워커·공유 메모리 계약을 유지한다. 두
산출물은 각각 빌드해야 하며 이 설정만으로 자동 선택되지는 않는다.
WebGL2를 제공하지 않는 브라우저는 지원하지 않는다. WebGL의 내부 위젯 표면은 투명 배경을 허용하며 공개 원시 캔버스는 기존의 불투명 배경 계약을 유지한다.

Emscripten의 헤더 기반 iiGUI 빌드는 C++ 모듈 스캐너를 기본 요구하지 않는다. `CMAKE_CXX_SCAN_FOR_MODULES`를 명시한 경우 소비자 설정을 따른다.

Core의 기존 기본 옵션은 pthread 사용이다. 일반 브라우저용 단일 스레드 산출물은
Core를 `IISDKCORE_WASM_THREADS=OFF`로 먼저 빌드·설치한 뒤 iiGUI를 그 Core
패키지로 구성한다. iiGUI는 패키지의 스레드 옵션을 따르며 명시한 설정이 패키지와
다르면 실패한다. 멀티스레드 산출물에는 서버의 교차 출처 격리와 지원되는 브라우저가
필요하다. 단일 스레드 빌드는 멀티스레드 작업을 자동으로 병렬 실행하지 않는다.

웹 글꼴 등록은 워커의 `self.fonts` 또는 브라우저 메인 스레드의 `document.fonts`를
사용한다. 글꼴 집합이나 `FontFace`를 사용할 수 없는 경우 등록 실패를 보고한다.

설치된 iiGUI 패키지를 사용하는 앱에서도 Core와 iiGUI의 스레드 모드를 검사한다.
서로 다른 공유 메모리 ABI를 가진 패키지를 섞으면 구성 단계에서 거부한다.
