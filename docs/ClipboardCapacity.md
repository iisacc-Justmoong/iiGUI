# 클립보드 텍스트 용량

`iiGUI::write_clipboard`와 `read_clipboard`는 1 MiB를 넘는 유효한 UTF-8 텍스트도
처리해야 한다. Dreamscapes 실패 보고서가 사용하는 최대 64 MiB까지 원문을 자르지 않고
전달하며, 그보다 큰 값이나 NUL·잘못된 UTF-8은 네이티브 클립보드를 수정하기 전에
거절한다. 파일·URL·이미지의 기존 검증은 유지한다.

각 플랫폼의 읽기 한도는 공통 텍스트 용량과 일치해야 한다. Web은 읽을 때 최대 용량을
미리 할당하지 않으며, Wayland 전송은 실제로 진행되는 동안 기다리고 중단된 전송은
기한으로 종료한다. 플랫폼 권한과 운영체제의 별도 제한은 성공으로 위장하지 않는다.
macOS 검사는 사용자의 일반 클립보드가 아닌 고유한 테스트 페이스트보드를 사용한다.
Android 클립보드의 JNI UTF-16 조회에도 공통 용량을 적용한 뒤 UTF-8 바이트 한도를
검사한다. 다른 JNI 문자열 조회에는 기존 한도를 유지한다.

공개 상수 `maximum_clipboard_text_bytes`는 UTF-8 바이트 기준 64 MiB이다. 시스템
클립보드가 더 작은 제한이나 권한을 적용하면 해당 실패를 그대로 반환한다. 입력
텍스트를 검증하기 전에 기존 클립보드를 비우지 않는다.

`iiGUI.clipboard_capacity`는 2 MiB 초과와 64 MiB 경계, 잘못된 UTF-8과 NUL을
검사한다. `iiGUI.clipboard_capacity_mac`은 독립 페이스트보드에서 대용량 다국어
왕복과 거절 후 보존을 검사한다. Web 경로는 Node의 메모리 전용 클립보드 모의에서
2 MiB 왕복과 거절 후 보존을 검사했다. iOS 및 Android 경로는 객체 컴파일만 확인했으며,
Windows·Linux와 실제 브라우저·모바일 장치의 클립보드 실행 검증은 포함하지 않는다.
