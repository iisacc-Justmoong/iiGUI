# 외부 그리기 장치를 사용하는 iiGUI 뷰

`PaintView`는 외부 호스트가 제공한 `PaintDevice`를 사용해 iiGUI 위젯 트리를
그리는 명시적 경로다. 앱은 생성된 C++ 위젯 팩토리, 표시 표면, 입력 이벤트와
그리기 호출 시점을 제공한다. 공통 페인터 계약은 운영체제 창이나 위젯 핸들을
받지 않으며 생성 시 화면을 띄우거나 타이머·스레드를 만들지 않는다. 플랫폼별
장치는 호스트에서 제공한 표시 표면을 별도로 받을 수 있다.

## LVUI를 빌드 입력으로 사용

앱은 호스트에서 실행 가능한 `lvui-compile`을 지정한다. 교차 컴파일에서도
컴파일러는 빌드 머신용 실행 파일이어야 한다. `iiGUI` 라이브러리에는 LVUI
파서나 컴파일러를 링크하지 않는다.

```cmake
find_package(iiGUI CONFIG REQUIRED)
iigui_compile_lvui(NAME Example SOURCE "${CMAKE_CURRENT_SOURCE_DIR}/Example.lvui"
    COMPILER "${LVUI_HOST_COMPILER}" OUTPUT_VARIABLE generated_view)
add_executable(example main.cpp "${generated_view}")
target_link_libraries(example PRIVATE iiGUI::iiGUI)
```

`Example.generated.h`의 `lvui_generated::Example::build`를 위젯 팩토리로
사용한다. `STYLE_FILE`, `STYLE_MODES`, `INCLUDES`를 선택적으로 전달할 수
있다. 컴파일에 실패하면 이전 결과는 유지되며 출력이 같으면 기존 파일의
수정 시각을 보존한다. 모든 LVUI 컴포넌트가 현재 별도의 LVUI 네이티브
어댑터 없이 생성되는 것은 아니다. 이 경로의 통합 검사는 단순한 Window,
VStack, Label 조합을 대상으로 한다.
`--view-factory`를 사용하는 위 CMake 경로는 `Host::mount_widgets` 대신
팩토리를 생성한다. 단일 장면 `Application`은 `make_application_owner`,
`activate`, `build_with_application`, `retire`를 외부 호스트가 명시적으로
연결한다. 호스트는 생성된 `window_geometry()`에서 최초 제목과 크기를 얻는다.
반응형 창 속성은 뷰를 구성할 때와 변경될 때 `window_geometry` 서비스에 전달된다.
복수 장면, 창 종료 가드, 팝업 마운트 검증이 필요한 입력은 해당
기능을 생략하지 않고 진단한다. 창 표시와 실제 플랫폼 입력 연결은 호스트의
책임이다. 일반 `lvui-compile`의 기존 호스트 생성 경로는 유지된다.

## 장면, 입력과 수명

`PaintDevice` 구현체는 클립, 배경 재질, 그림자, 변환 및 장면 참조를 포함한
전달 순서를 지키고 배치된 패널·텍스트·이미지를 그린다. 장치의 기능을 먼저
선언하며 지원하지 않는 효과나 필수 하드웨어 조건은 프레임 시작 전에
거부한다. `Painter`는 올바른 장면 의존 순서를 계산하고 크기와 형식이 잘못된
입력을 거부한다. 오류나 취소 시 공급자는 불완전한 프레임을 폐기해야 한다.
`present()`가 성공한 뒤에는 이미 확정한 프레임을 취소할 수 없다. 전체 장면을
직접 받는 `FramePaintDevice`는 검증된 프레임의 제출 성공을 반환하며 비동기 GPU
완료까지 기다렸다는 뜻은 아니다. 입력 참조는 호출이 끝나기 전까지만 유효하다.

호스트는 `PaintViewServices`에 iiSDKCore 이벤트 루프와 같은 루프에 결합된
프레임 루프를 전달할 수 있다. 변경 알림은 이벤트 루프에서 합쳐 전달되며
`needs_paint()`로 미처리 상태를 조회할 수 있다. 입력은 `input`, 필요한 그리기는
`paint`로 명시적으로 요청한다. `frame_activity(true)`는 호스트가 디스플레이
프레임을 공급해야 함을, `false`는 그 요청이 끝났음을 알린다. 콜백은 프레임
예약만 변경하고 뷰를 동기적으로 파괴하거나 재진입해서는 안 된다. 창 속성은
`window_geometry`로 제공한다. 루프들은 뷰보다 오래 살아야 하며 뷰의 소유
스레드에서 구동해야 한다. 자동 주기 갱신과 백그라운드 폴링은 없다.

뷰의 생성·입력·그리기·종료와 마지막 소유권 해제는 같은 스레드에서
이루어져야 한다. 그리는 중 종료가 요청되면 아직 확정되지 않은 작업을
취소한 뒤 위젯과 구독을 정리한다. 공급자는 메서드 인자로 받은 span과
참조를 호출 이후까지 보관해서는 안 된다. 장치의 그리기 콜백에서는 위젯
트리의 재진입 변경을 거부한다. 콜백 중 종료 요청은 허용하며 정리는 현재
프레임이 중단된 뒤 수행한다. 마지막 소유권을 해제할 때도 위젯과 구독을
그리기 장치보다 먼저 정리한다.

## 현재 구현 범위

`find_package(iiGUIPainter)`의 `iiGUI::Painter`만 링크하면 장면 검증과
페인터 계약을 기존 창 호스트 없이 이용할 수 있다. `PaintView`와 그 위젯의
공개 헤더는 창 크기 자료형을 위해 `Host.h`를 포함하지 않는다. 다만 `PaintView`와
GPU 구현의 바이너리는 아직 전체 `iiGUI` 라이브러리에 포함되며 Cocoa·Win32·
Wayland 호스트도 그 라이브러리에 남아 있다. 따라서 위젯 및 GPU 라이브러리의
호스트 링크 분리는 아직 완료되지 않았다. `iiGUI::HostBridge`의 `HostFramePaintDevice`는 기존
호스트의 GPU 장면 경로에 전달하며 해당 호스트의 기존 캔버스·마운트를 교체한다.
호스트는 입력을 별도로 `PaintView::input`에 전달하고 현재 배율과 장치 기능을
제공해야 한다. 창이 열리지 않은 호스트는 프레임을 수락하지 않는다.

Apple 대상의 `MetalPaintDevice::create`는 호스트가 만든 `CAMetalLayer`를 받아
기존 Metal 장면 렌더러에 직접 연결한다. 장치는 레이어를 소유 기간 동안 유지하며
네이티브 창이나 뷰를 생성하지 않는다. 호스트는 다른 렌더러와 동시에 그 레이어를
사용하지 않아야 한다. 장치는 Metal 장치, 픽셀 형식, 색 공간, 배율, 드로어블
크기와 표시 설정을 구성한다. 드로어블을 받지 못하면 그리기는 실패하고 미완성
프레임을 중단하고 장면 캐시를 무효화한다. 이후 표면이 다시 사용 가능해졌다는 호스트
이벤트에 따라 `needs_paint()`를 확인하고 다시 요청한다. Metal은 원본 이미지
텍스처의 샘플링과 색조·투명도·모서리·테두리·그라데이션 합성을 GPU에서 수행하고,
변하지 않은 원본 텍스처를 재사용한다. 한 표면에서 유일한 이미지 원본 텍스처의
합계는 512 MiB로 제한한다. 텍스트는 여전히 플랫폼 서비스에서 CPU로 래스터화한다.

`VulkanPaintDevice::create`에는 호스트가 필요한 인스턴스 확장 이름과 표면 생성
함수를 전달한다. 렌더러가 자신의 Vulkan 인스턴스를 만든 다음 생성 함수를
호출한다. 반환된 `VkSurfaceKHR`의 소유권은 렌더러에 이전되어 장치 종료 시 파기된다.
호스트의 창·디스플레이와 생성 함수가 참조하는 상태는 장치보다 오래 살아야 한다.
표면을 표시할 수 없으면 `busy`를 반환하며, 호스트는 표면의 준비 또는 크기 변경
이벤트를 받은 뒤 명시적으로 다시 그린다.
획득한 이미지에 대한 프레임이 제출 전에 실패하면 동기화 신호를 정리하고 다음
요청에서 스왑체인을 교체한다. GPU 완료를 확인할 수 없는 오류에서는 장치 재생성이
필요하며 자동 재시도하지 않는다. 창 없는 Vulkan headless 표면 검사에서 요청 전
취소, 잘못된 스레드·크기, 변경된 프레임, 보존된 프레임과 크기 변경 후 제출을 확인했다.
macOS의 정적 빌드에서는 Vulkan 장면의 패널과 배경 픽셀도 GPU에서 읽어 확인했다.
획득 후 실패에 대한 실제 드라이버 오류 주입과 운영체제 창 표시는 검증하지 않았다.

Windows의 `Direct3DPaintDevice::create`는 호스트가 만든 D3D11 `IDXGISwapChain`을
받아 참조를 유지한다. 호스트는 원하는 픽셀 크기와 단일 샘플 RGBA8 형식으로
스왑체인을 준비·크기 조절하고, 장치가 살아 있는 동안 즉시 컨텍스트와 스왑체인을
독점적으로 이 페인터에 맡긴다. 페인터는 플랫폼 창을 만들지 않는다.

시스템 입력, 텍스트 입력기, 접근성 및 표시 표면 연계는 외부 호스트 또는
어댑터의 작업이다. 새 페인터 인터페이스의 Python API는 아직 없다.
Windows·Linux의 실제 표시 표면과 GPU 출력은 이번 변경으로 검증되지 않았다.
Windows 코드는 교차 컴파일러의 구문 검사만 수행했다. macOS의 창 없는 Metal
이미지 테스트는 셰이더의 픽셀 결과를 CPU 기준과 비교하며, 기록 장치 테스트는
장면 순서, 입력, 갱신 요청, 취소·수명과 LVUI 생성 코드를 확인한다. 이들은
실제 앱 창의 표시를 검증한 결과가 아니다.
