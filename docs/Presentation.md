# 프레임 제출 원천

PresentationSource는 프레임 제출·종료를 읽는 교체 가능한 C++ 인터페이스이다.
PresentationStream은 렌더러가 소유하는 발행 객체이며, Host::presentation_source는 읽기
인터페이스만 반환한다. Host마다 원천이 다르고 원천을 보관해도 창의 수명은 연장되지 않는다.
모든 읽기·발행·소유자 종료는 생성 스레드에서 수행한다. 관측 lease의 해제는 다른 스레드에서도
가능하다. 실제 원천의 파괴는 생성 스레드에서 한다.

NativeCanvas는 draw 전후의 실제 presentation 카운터를 대조한다. 요청만 있거나 그리기가
실패한 경우에는 발행하지 않는다. 렌더러 fallback으로 카운터가 초기화된 경우도 새 제출을
인식한다. capture와 읽기 전용 스냅샷은 제출을 만들지 않는다. 관측자가 없으면 telemetry용
info 조회·콜백 전달을 추가하지 않는다. Windows·X11의 기본 텍스트 경로도 성공한 제출 뒤에
같은 원천을 사용하며, 이 소프트웨어 경로의 GraphicsApi는 none이다.

Host는 기존 Core 이벤트 루프에 전달한다. 시각은 렌더러 제출 직후 캡처하며, 이 경로는
scanout·GPU 완료·사용자에게 실제 보인 시각의 측정이 아니다. 별도 런타임이나 타이머는
만들지 않는다. 부모 창의 루프로 연결된 자식 창에서도 현재 실행 루프로 전달하며 자기 원천을
유지한다. Source의 직접 모드는 독립 C++ 렌더러·시험용이며 Host는 항상 지연 모드를 쓴다.

대기 토큰은 완료된 것을 회수하고 최대 2048개로 제한한다. Core 큐의 포화·잘못된 동기
실행기·전달 거부는 원천 종료와 오류 이벤트로 표시한다. 스레드 계약을 위반한 실행기의
콜백은 GUI 상태를 바꾸지 않고 실패 수에 기록한다. 관측 오류는 다른 관측자를 건너뛰거나
이미 제출한 프레임을 롤백하지 않는다. 종료는 예약 토큰을 취소하며, 실행 중 콜백의 자기
대기를 만들지 않는다. callback 관측은 Core Observable과 RAII lease를 사용한다.

창 없는 원천·경계 검사는 별도로 실행한다. 플랫폼 소스 연결 감사와 해당 호스트 컴파일은
실제 창·GPU·다른 OS 실행의 증거를 대신하지 않는다. LVRS RenderMonitor와 실제 AOT 뷰의
실행은 LVRS 작업 지침에 따라 전체 작업의 마지막에 모은다.
