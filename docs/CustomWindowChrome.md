# 사용자 정의 네이티브 창 프레임

`HostOptions::chrome`의 기본값은 `WindowChrome::system`이다. 창을 열기 전에
`WindowChrome::custom`을 지정하면 데스크톱 앱이 일반 위젯 트리에서 타이틀바를
제공할 수 있다. `window_chrome_presentation(backend)`는 타이틀바와 기본 창
버튼 또는 앱이 그리는 버튼의 표시 정책을 구분한다.

- macOS에서는 콘텐츠가 투명 타이틀바까지 확장되고 기본 제목은 감춰진다.
  AppKit 창 버튼과 크기 조절을 유지하므로 뷰는 버튼 공간을 비워야 한다.
- Windows에서는 클라이언트 영역으로 프레임을 확장하고 가장자리의 네이티브
  크기 조절 판정을 유지한다. X11에서는 창 관리자에 제목과 버튼 제거를 요청하고
  크기 조절 테두리는 남긴다. Wayland에서는 클라이언트 가장자리의 크기 조절을
  컴포지터에 요청한다. 세 플랫폼의 뷰는 자체 창 버튼을 제공해야 한다.
- iPadOS와 Android는 창 버튼 없이 앱 타이틀바를 사용할 수 있다. 창 형상은
  운영체제가 관리한다. 웹과 지원하지 않는 호스트는 이 정책을 활성화하지 않는다.

창 닫기는 `Host::request_close()`를 호출하여 기존 닫기 승인 절차를 거친다.
최소화와 최대화·복원 전환은 각각 `Host::window_action()`의 `minimize`와
`toggle_maximize`를 사용한다. 창 제어의 실제 가능 여부는 운영체제와 창 관리자에
따른다. 특히 X11의 장식·이동·최대화 요청은 창 관리자의 Motif 및 EWMH 지원에
의존한다.

앱이 정의한 이동 영역의 기본 마우스 누름 처리 안에서
`Host::begin_window_drag()`를 동기적으로 호출한다. 호스트는 위젯 포인터 캡처를
취소한 뒤 창 이동을 운영체제에 넘긴다. Wayland에서는 해당 누름의 직렬 번호를
보존해 컴포지터에 전달한다. 이동 영역에 버튼 등 대화형 위젯을 포함하지 않는다.

`HostOptions`의 레이아웃이 변경되므로 소비자와 iiGUI 라이브러리를 같은 헤더로
다시 빌드해야 한다. 호스트 정책 및 Wayland 모의 이벤트 검사는 실제 Windows나
Linux 창 관리자에서의 실행 검증을 대신하지 않는다.
