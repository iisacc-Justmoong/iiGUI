# 네이티브 스크롤 뷰포트

`WidgetBuilder::scroll_view`는 하나의 정적 C++ 콘텐츠 루트를 가지는 수직 뷰포트이다.
OS 스크롤 컨트롤이나 별도 이벤트 루프를 생성하지 않는다. `ScrollOptions`의 width와
height가 양수이면 원하는 크기이며, 0은 콘텐츠의 자연 크기를 사용한다. 세로 스택에서
`set_flex`를 주면 고정 헤더·여백을 제외한 남은 높이를 배분한다. 기존 가로 flex와
기본 스택의 배치는 유지한다.

`set_scroll_offset`은 유한 값을 받으며 0부터 `content_height - viewport.height`까지
제한한다. 콘텐츠 변경과 창 크기 변경도 오프셋을 다시 제한한다. `enabled=false`는
스크롤을 멈추고 콘텐츠 높이를 뷰포트 높이에 맞추지만, 자식의 입력 활성 상태는 바꾸지
않는다. 프로그램 방식으로 오프셋을 지정하는 API와 포인터 휠의 활성 정책은 별개이다.

휠·트랙패드는 포인터 아래 가장 안쪽 뷰포트에 먼저 전달한다. 해당 방향의 끝에 도달하면
바깥 뷰포트로 전달한다. 자식의 키보드 포커스 이동은 조상 뷰포트를 안쪽부터 조정하여
대상을 노출한다. 숨겨진 항목도 논리적 Tab 순서에 남지만 포인터 hit test·가상 접근성의
가시 경계·GPU 표시는 교차한 뷰포트 영역을 사용한다. 작은 스크롤 표시기는 iiGUI가 그린다.

각 뷰포트의 교차 clip은 네이티브 GPU scissor이다. 연속된 동일 clip은 같은 레이어에
모으며 뷰포트를 벗어나면 이전 clip을 복원한다. 자식의 이미지 샘플링 좌표를 잘라
늘리지 않으며, 헤더·다음 형제의 clip에도 영향을 주지 않는다. 콘텐츠 좌표가 바뀌는
스크롤에는 보이는 전경의 래스터 갱신이 필요하다. 모든 콘텐츠를 보관하는 타일 캐시나
대규모 목록 가상화·터치 관성·스크롤바 직접 드래그는 아직 구현 범위에 포함하지 않는다.
캔버스의 기존 64개 오버레이 제한도 유지된다.

`WidgetSnapshot`의 `scroll_offset`, `content_height`, `clip_bounds`와
`visual_clip_bounds`로 상태를 관찰한다. 팝업 안에서는 같은 팝업의 변환·모달 입력 경계를
따른다. 콘텐츠 팩토리가 생성한 별도 세대와 중첩 팝업의 모든 변환 조합은 완전한 플랫폼
동등성 검증 범위가 아니다. 현재 macOS의 가상 접근성 역할은 scroll area이며 실제 OS
컨트롤은 만들지 않는다. Windows/Linux의 위젯 입력 어댑터 검증은 남아 있다.

`iiGUI.scroll_view_*`는 경계·크기 변경·입력·중첩·포커스 노출·실제 GPU 클리핑을 검사한다.
LVRS Sheet는 고정 헤더와 본문 뷰포트를 이 계약으로 조합한다.
# 가상 데이터 화면

큰 논리 content height, viewport 변경 수신, 지역 좌표의 보관형 그리기와 C++ 입력
가로채기는 [VirtualViewports](VirtualViewports.md)에 기록한다. 이 확장의 실행 검증은
최종 일괄 단계까지 유보한다.
