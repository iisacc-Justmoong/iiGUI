# LVUI callable 필드의 네이티브 위젯 연결

`get()`·`revision()`을 제공하지만 자체 관측 통지가 없는 필드도 검사한다. 모델의 명령이
함수를 교체한 뒤 생성 스코프의 변경 발행을 통해 동일한 버튼이 새 함수를 사용해야 한다.

`tests/native_callable_fields.cpp`는 LVUI가 생성한 C++ 팩토리를 창 없는 `WidgetState`에
연결한다. 실제 OS 창이나 GPU 표면을 만들지 않으며 LVRS 앱 실행을 대신하지 않는다.

검사 대상은 관측 가능한 함수 필드와 공유 핸들, typed 함수 입력·기본값·문자열 이벤트,
Static·가변 함수의 초기 선택, 비복사 함수 객체의 차용, 임시 부모와 선택된 중첩 객체이다.
필드 게시 후 동일한 위젯 ID·입력 내용·포커스가 유지되고 파일 리비전이 바뀌지 않아야 한다.
null·빈 함수의 재게시 실패는 이전 연결·표시를 유지하고 이후 정상 게시로 복구한다.
실행 중 교체·재진입·자기 화면 제거는 원래 함수와 수신자를 반환까지 보존해야 한다.

설치·경로 이동 소비자는 실제 설치한 LVUI 생성기로 함수 필드의 typed 표시와 버튼
팩토리를 생성하고 컴파일·링크한다. 생성 위젯의 실행 검사는 위의 창 없는 대상에서
별도로 수행한다. 일반 C++ 차용 필드의 외부 교체·파괴는 소유 API의 책임이다.

언어·소유권 계약은 [LVUI callable 필드](../../LVUI/docs/CallableFields.md), 전체 완료
경계는 [완료 감사](../../LVUI/docs/Completion.md)를 따른다. 실제 측정 결과와 제한은
각 검사 이후의 LVUI 검증 기록으로 연결한다.

2026-10-26 macOS arm64에서 기존 창 없는 동작과 생성 C++ 검사 197개를 일반·ASan·UBSan
빌드에서 각각 통과했다. 새 필드 동작은 각 11개이며, 전체 수와 합산하지 않는다.
설치·경로 이동 소비자의 함수 필드 팩토리도 컴파일·링크했다. 실행 파일의 Qt 동적 의존성과
LVUI 파서·컴파일러 실행 심볼은 없다. 원시 증거는 LVUI의
`build/lvui-completion/callable-fields-verification-20261026.json`에 기록한다.
