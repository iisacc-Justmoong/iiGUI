# 편집기 입력과 텍스트 서비스

`WidgetInput`은 논리 좌표와 함께 포인터 종류·장치 ID·압력·기울기(도)·회전(도)·단조 시각(초), 버튼 비트와 Shift/Control/Alt/Meta를 전달한다. 정밀 휠은 가로·세로 논리 델타를 보존한다. 마우스의 기본 압력은 1이며 펜의 접촉 압력은 0~1이다. 비유한 값과 범위 밖 압력은 명령 전달 전에 거부한다.

입력 처리기가 소비한 누름은 해당 처리기에 이동·해제를 캡처하고 키보드 초점을 준다. 포커스 상실·뷰 폐기·숨김 시 캡처를 해제한다. 상위 단축키 처리기는 `text_input_active`를 확인하여 텍스트 입력 중 도구 변경을 억제할 수 있다. 플랫폼별 일반 문자 키는 `WidgetKey::character`와 수정키 없는 `text`로 전달한다.

포커스된 기본 입력 필드의 비밀번호·여러 줄·읽기 전용 속성과 활성 상태를 바꾸면
플랫폼 표면이 변경이 적용된 뒤 이를 관찰할 수 있어야 한다. 필드 비활성화로
포커스가 사라지는 경우에도 최종 상태를 전달한다. UIKit은 이 통지를 이용해
현재 입력기의 속성과 키보드 표시 상태를 갱신한다.

누름 콜백이 실행 중일 때도 같은 위젯에 임시 캡처를 둔다. 콜백이 포인터 해제나
포커스 취소를 재진입시키면 영역 밖의 해제도 원래 처리기로 전달하고, 이전 누름의
반환이 끝난 캡처를 다시 만들지 않는다. 처리기가 누름을 거절하면 임시 캡처는 되돌린다.
임베디드 콘텐츠는 같은 포인터 입력 세대를 공유하므로 다른 하위 호스트에서 발생한
새 누름·해제도 이전 누름보다 우선한다. 독립 입력 스레드나 복수 동시 캡처를 뜻하지 않는다.
`iiGUI.ancestor_input.reentrant_release`와 LVUI의 호스트 입력 검사는 이 순서와 다음
제스처의 복구를 합성 이벤트로 확인한다.

문자 입력을 소유한 사용자 정의 편집기는 인쇄 가능한 공백을 key-down과 text로
중복 삽입하지 않고 text 이벤트로 받는다. UIKit 하드웨어 키보드에서 편집 중인
수정키 없는 공백은 text service에 맡기며, 버튼과 수정키 단축키는 기존 키 입력을
유지한다. 실제 기기 키보드 검증은 별도로 필요하다.

IME의 `replacement_range`와 `composition_selection`, 스냅샷의 선택·조합 범위는 UTF-16 단위이다. 내부 편집은 UTF-8 스칼라 경계에서만 일어난다. 서로게이트 중간 범위를 거부하고, 조합 문자열은 확정 전 문서 텍스트를 변경하지 않는다. `InputOptions.multiline`은 Enter를 줄바꿈으로 처리하며 Control/Meta+Enter는 제출한다. 복사·잘라내기·붙여넣기는 네이티브 클립보드와 현재 선택을 사용한다.

공통 `text_selection` 입력은 포커스된 편집기의 새 UTF-16 선택을
`replacement_range`에 전달한다. 정상 범위와 스칼라 경계를 검증하며 읽기 전용
편집기에서도 사용할 수 있다. 선택을 소유한 사용자 정의 텍스트 제공자는 길이 0인
읽기로도 스칼라 경계를 검증하고, 같은 위젯의 입력 핸들러에서 선택을 반영한다.
범위는 정규화하며 `selection_reversed`가 비어 있지 않은 역방향 선택의 anchor와
caret을 구분한다. 기본 입력 필드는 조합 중 범위 안팎의 선택을 보존한다.
`text_cursor_offset`은 조합 또는 확정 텍스트 교체와 커서 이동을 함께 요청하며,
빈 조합과 기존의 조합 취소를 구분한다. `text_service` 입력은 명시적인 포커스
대상에만 전달하고 상위 단축키 핸들러가 가로채지 않는다. `text_selection_after`는
교체 결과의 UTF-16 선택과 기존 `selection_reversed` 방향을 함께 요청한다.
커서 오프셋과 동시에 지정할 수 없고, 잘못된 결과 범위는 교체 전에 거절한다.
기본 입력 필드의 확정 텍스트 교체 범위는 조합 후보를 포함한 표시 문서를
기준으로 한다. 후보 안팎이나 경계를 걸치는 교체는 후보 확정과 함께 적용하며,
잘못된 경계 또는 결과 선택은 원본과 후보를 보존한다.
`text_composition_region`은 `text_service`와 포커스 대상을 지정하고 기존 표시
문자열의 UTF-16 영역을 `replacement_range`에 담는다. 문자를 바꾸거나 방향성
선택을 옮기지 않고 영역을 조합 대상으로 표시하며 빈 영역은 기존 조합을 확정한다.
기존 후보가 있으면 새 영역의 준비와 검증을 마친 뒤 후보를 확정한다. 기본 입력
필드는 이 확정으로 실제 문자가 바뀐 경우에만 편집 콜백을 발행한다. 범위 밖·잘못된
스칼라 경계나 표시 문자열을 보존할 수 없는 확정은 기존 상태를 유지하며 거절한다.
`text_surrounding_delete`는 포커스된 조합 편집기의 선택을 포함하는 UTF-16 범위를
받고 선택 앞뒤만 삭제한다. 조합과 삭제가 겹치면 후보를 줄이고 조합 밖의 삭제는
원본에 반영한다. 역방향 선택과 조합 표시를 유지하며 두 구간은 하나의 요청으로
검증한다. 이 이벤트도 `text_service`, 명시적 대상과 유효한 범위가 필요하다.
사용자 정의 `TextInputProvider`는 문자·선택·조합이 바뀔 때마다 다시 쓰지 않는
`TextInputState::revision`을 제공할 수 있다. 값이 소진되면 생략해야 한다. iiGUI는
위젯 수명·공급자와 포커스의 세대를 함께 묶은 불투명 `TextInputRevision`을
스냅샷에 노출한다. 입력기의 `expected_text_revision`을 지정하면 실제 텍스트
핸들러에 전달하기 직전에도 이를 검사한다. 다른 스레드가 공유 문서를 바꿀 수
있으면 앱의 핸들러는 원본 버전 비교와 편집을 같은 원자적 작업으로 수행해야 한다.
버전 없는 기존 제공자는 다른 위젯 경로를 유지하지만 Android 입력기는 이 제공자의
조회·편집 요청을 거절한다.
이 입력을 사용하는 앱과 iiGUI는 같은 헤더 ABI로 다시 빌드해야 한다.
[Android 연결 명세](AndroidIME.md)는 별도이다.

### 텍스트 범위의 화면 기하 계약

네이티브 입력기는 포커스된 커서뿐 아니라 임의의 UTF-16 범위에 대한 양 끝 커서와
선택 영역을 조회한다. `Widget::set_text_geometry_provider`로 등록하는 선택적 기하 제공자는 위젯의 로컬 좌표로
양 끝 커서와 보이는 선택 영역들을 반환한다. iiGUI는 위젯·중첩 콘텐츠·팝업의 배치와
변환을 적용하여 표면 좌표를 제공한다. 다중 줄과 양방향 텍스트의 분리된 선택 영역은
각각 유지한다. 화면 밖의 커서는 크기가 0인 사각형으로, 화면 밖의 선택은 빈 목록으로
나타낸다. 오류, 잘못된 UTF-16 범위, 비유한 좌표, 비정상 크기 또는 과도한 결과는
거부한다. 기존 텍스트 제공자의 자료형을 변경하지 않으며, 텍스트 제공자를 교체하면
연결된 기하 제공자는 제거된다. 기하 제공자가 없는 위젯은 조회에서 `unsupported`를 반환하며 기존 문자
입력은 유지한다. 조회 중 제공자나 위젯이 폐기되면 이전 결과를 반환하지 않는다.

이 계약은 입력기의 후보창과 선택 UI에 필요한 공통 데이터이다. UIKit 어댑터의
조합·선택 연결과 범위 제한은 [iPadOS 입력 계약](IPADOS.md#uikit-텍스트-입력-계약)에
기술한다. 실제 장치 동작은 별도로 검증해야 한다.
macOS 헤드리스 `iiGUI.text_geometry`는 중첩 콘텐츠와 팝업의 좌표 변환, 조상
클리핑·숨김, 스칼라 경계, 제공자 교체·퇴역·재진입, 조회 중 버전 변경과 잘못된
결과를 검사한다. 변경된 iiGUI와 LVUI 입력 소스는 iPhoneOS arm64 객체까지
컴파일했다. 이는 입력기 실행의 증거가 아니다.

사용자 정의 텍스트 제공자가 입력기 외부에서 텍스트나 선택을 변경한다면 위젯의
`begin_text_input_change`로 얻은 범위를 변경 전부터 변경 종료까지 유지한다.
첫 번째 인자는 텍스트 변경 여부이고 두 번째 인자는 시스템 입력기 자체의 요청
여부이다. 이는 플랫폼에 변경 전후를 전달하기 위한 선택적 계약으로, 중첩된 앱
편집과 시스템 요청을 구분한다. 제공자의 버전 검증과 편집의 원자성은 여전히
제공자가 책임진다.

Cocoa의 `NSRange`는 `ii::gui::TextRange`로 변환하며 `size_t` 범위를 보존한다.
Apple의 동명 CoreServices 자료형과 혼동하거나 32비트 필드로 축소하지 않는다.

macOS의 Copy/Paste 명령은 편집기가 활성화된 경우 기존 문자 선택 경로를 유지한다.
그 외의 자체 컨트롤에는 copy 키와 `WidgetInput.content`를 가진 text 이벤트를 전달한다.
이 때문에 표는 행렬을 붙여넣고 편집기는 문자를 붙여넣을 수 있다. 전체 클립보드 payload는
기존 크기·UTF-8 검증을 거치며 Source text 필드의 65,536바이트 한도와 구분한다.

`iiGUI.editor_input`은 압력과 보조키 보존, 화면 밖 캡처·취소, UTF-16 교체·잘못된 서로게이트, 한글 조합·확정, 다중행, 단축키 보호와 속성 바인딩 해제를 실제 Host에서 검사한다. 이 합성 입력 검사는 물리 펜 하드웨어 검증과 구분한다.

## Windows 입력기 조합 계약

Windows IMM의 [조합 메시지](https://learn.microsoft.com/en-us/windows/win32/intl/wm-ime-composition)는 여러 변경 플래그를 함께 전달할 수 있다.
확정 문자열과 현재 후보는 각각 읽고 둘이 함께 있으면
확정, 후보 순서로 전달한다. 두 문자열과 후보 커서를 전달 전에 검증하며, UTF-16의
짝이 맞지 않는 서로게이트, 중간에서 끊어진 읽기, 범위 밖 커서와 과도한 문자열은
편집 전에 거절한다. 후보 문자열의 길이 0은 빈 조합으로 유지하고, 변경 플래그가
없는 취소 메시지 또는 조합 종료는 확정 전 후보만 취소한다. 커서 위치만 변경된
메시지는 현재 후보를 다시 조회해 선택을 갱신한다.

입력 세션은 시작 시 포커스된 편집기에 묶인다. 문자열 확정 콜백이 포커스를 바꾸면
같은 메시지에 포함된 후속 후보는 새 편집기에 전달하지 않는다. 버전이 있는 제공자는
위젯 소유권과 포커스 세대를 함께 검사하고 각 편집 직전의 상태 버전을 전달한다.
버전 없는 기존 사용자 제공자는 같은 ID와 현재 포커스로 호환 처리하므로 같은 ID를
재사용한 포커스 왕복을 구별하지 못한다. 이 경로는 Windows IME 실기기 실행이나
모든 IME 확장 메시지의 지원을 뜻하지 않는다. 같은 세션의 전달 중 재진입한 입력은
대기하지 않고 거절한다. 확정 콜백이 같은 편집기의 텍스트를 다시 바꾼 경우에는
후속 후보의 의미가 새 내용과 일치하는지 판단하지 않는다.

일반 Windows 문자 메시지에서는 UTF-16의 상위 서로게이트를 같은 편집기의 다음
하위 서로게이트와만 결합한다. 잘못된 하위 문자는 버리고, 상위 문자가 빠진 뒤
일반 문자가 오면 새 문자는 유지한다. 포커스 세대가 바뀌거나 창이 포커스를 잃으면
대기 중인 상위 문자를 폐기한다. 버전 없는 제공자의 동일 ID 재사용은 구별할 수 없다.

2026-11-05에 위젯 입력 소스와 합성 검사 소스를 LLVM-MinGW 20260908의 Windows
x86-64·ARM64 대상으로 각각 COFF 객체 컴파일했다. macOS 헤드리스 입력 검사 4건과
LVUI 필드·코드 편집기 연결 검사 2건이 통과했고, Windows 입력 프로토콜 검사는
AddressSanitizer와 UndefinedBehaviorSanitizer에서도 통과했다. 전체 Windows 라이브러리·앱 링크와
실제 Windows 입력기는 실행하지 않았다. IMM의 절별 스타일, `CS_INSERTCHAR`,
`WM_UNICHAR`와 TSF 텍스트 서비스는 이 구현에 포함되지 않는다.

## XInput 펜 센서 상태

XInput의 펜 및 지우개 입력은 source device별로 마지막 유효한 압력·기울기·회전을 유지한다. 장치를 처음 확인할 때 가능한 현재 축 값을 읽고, 이후 이벤트에는 축 마스크에 포함된 값만 반영한다. 따라서 센서 축이 없는 버튼 누름·떼기에는 마지막으로 확인된 표본이 전달되며 명시적으로 전달된 0은 새 값으로 반영된다. 비유한 축이 있는 갱신은 전체를 거부하고 이전 표본으로 이벤트를 전달해 누름·떼기를 잃지 않는다. 터치와 마우스는 이 펜 상태를 공유하지 않는다.

보존한 값은 최종 이벤트의 실제 측정값이 아니라 해당 장치에서 마지막으로 관찰한 값이다. XInput의 기존 `Abs Rotation` 축은 그대로 사용하며, `Abs Wheel`이 회전과 슬라이더를 겸하는 경우 이를 추정으로 분리하지 않는다. [XWayland 소스](https://raw.githubusercontent.com/mirror/xserver/master/hw/xwayland/xwayland-input.c)는 이런 축 결합과 회전의 원점·배율 변환을 보여 준다. XInput 장치 종류·축 변경의 동적 재검색, 혼합 축 판별, Wayland 태블릿 프로토콜 및 실제 Linux 펜 기기 검증은 별도다.

`iiGUI.xinput_pen_state`는 센서 값이 빠진 버튼 입력, 한 축만 바뀐 입력, 명시적 0, 서로 다른 장치와 유효하지 않은 값의 원자적 거부를 순수 합성 상태 검사로 확인한다. 이 검사는 X 서버 또는 펜을 실행하지 않는다.
